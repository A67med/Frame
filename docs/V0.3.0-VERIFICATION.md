The initial full frontend suite ran 2,554 tests: 2,552 passed, one skipped, one
failed. `tests/removed-trackers.test.ts` searches for a literal LF after a function
signature in untouched tracker clients; their CRLF source makes its slice start
at the wrong position. Running that same test on an untouched archive of
`271b08ea` reproduces the failure. No tracker code or unrelated tests were changed.

The settings baseline failures concern existing portal/z-index/close checks,
identity-transform keyframes, unused settings, stale search anchors/tabs, and
ambiguous labels. Full baseline and changed-tree outputs were compared, rather
than treating a nonzero validator exit as a new UI regression.

Vite reports existing large chunks and mixed dynamic/static imports. Native
compilation reports warnings in untouched Rust/vendor code. This UI branch does
not attempt backend cleanup to silence them.

## Build preparation

- Sidecars, libmpv and VC++ runtime DLLs were copied from the original checkout
  into gitignored paths in this worktree. No binary is committed.
- `node scripts/copy-vc-runtime.mjs` selected an SQL Server Management Studio
  installation without the needed CRT directory. Copying the existing three
  CRT DLLs from the original checkout supplied the missing build resources.
- The compatibility jars are absent. Capstan staging used
  `HARBOR_CAPSTAN_SRC=<nonexistent-temp-directory>` and
  `HARBOR_CAPSTAN_OPTIONAL=1`, explicitly producing a build **without extension
  support**. This is a local validation limitation, not a change to release setup.
- The temporary Tauri config contains `{"build":{"beforeBuildCommand":""}}`.
  Vite is built separately; no installer, signing, version or workflow changes.
- Native builds use this worktree's own target directory. No existing Frame
  playback process was stopped. The native executable was not launched against
  the user's shared application-data profile.

## Visual and interaction verification

Actual app rendering was captured using headless Chrome through Playwright,
against Vite on `127.0.0.1:1421`. Baseline captures used the stable source, first
before edits and later from an untouched archive on port 1422. These are browser
frontend captures, not screenshots of a native Tauri window.

Live Cinemeta supplied the movie/TV artwork. No TMDB credentials, tracker
sessions or user library were copied. A bookmark was created only in the isolated
browser profile. Unavailable Radar/Following data is shown honestly.

Reviewed Home, movie/TV details, Discover, Radar, Following, library, search,
settings, movies/shows, catalogs, downloads, collections, addons, profile menu,
sign-in and onboarding. A generated 30-second H.264/AAC color-bar clip exercised
the actual HTML5 player; playing time advanced and Space paused it. This technical
test fixture is not represented as catalog content or native mpv verification.

Additional checks cover:

- Settings category navigation and cross-category subtitle search.
- Profile-menu Escape dismissal and retained focus outline.
- Inert inactive hero slides and no timed rotation under reduced motion/focus.
- Default/AMOLED opt-in and Royal/custom theme opt-out, without rewriting themes.
- A clearly labelled local long-title/missing-artwork fixture.
- 960×600 minimum, 1280×800, 1920×1080 and 2560×1440 viewports.
- Effective 1024×640, 853×533 and 640×400 layouts to probe 125/150/200% space
  constraints. These are CSS viewport approximations, not real Windows DPI tests.
- No document-level horizontal overflow in the tested Home/Settings sizes.

Early captures of lazy loading were rejected and recaptured after content loaded.
A hero-timer assertion during a code hot reload was repeated with stable code;
the stable pass succeeded. Screenshots are not treated as evidence merely because
the capture command returned successfully.

One later baseline Library capture hit a React `useReducer` runtime error in
the archived-source preview. It was excluded from the evidence set; the earlier
verified empty-library baseline capture is used instead. The redesigned populated
Library capture renders correctly. The final stable resilience/theme pass recorded
no JavaScript runtime errors.

## Remaining validation limits

Native libmpv playback, fullscreen/drag/maximize behavior, per-monitor Windows DPI,
real authenticated providers, large libraries, network-heavy download queues and
extension execution still need a configured native review. No startup, memory or
scrolling-performance improvement is claimed: no new dependency was added, but
there is no controlled before/after performance benchmark.

See [screen coverage](V0.3.0-SCREEN-COVERAGE.md) and
[visual evidence](v0.3.0-evidence/README.md). These limits must accompany review;
they are not hidden behind a claim of complete native validation.
