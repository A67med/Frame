# Frame v0.4.5 engineering report

## Release status

Release validation is in progress. This document is a record of observed results, not a publication announcement. The v0.4.5 tag, signed release assets, installation and upgrade checks must be verified before marking the release complete.

Its five local cleanup commits were preserved on `codex/v0.4.5` and merged with `origin/main` (`e52d4a2c`) in merge commit `5b0c367c`. The current interface and Theme Studio changes were retained. ## Branding

The shared loader, Big Picture intro, mobile setup mark and addon installation overlay still rendered Harbor boat artwork. They now use the existing Frame mark. Five unused loading-animation JSON assets were removed, including their Icons & animation gallery entries. Custom user loading artwork remains supported. Application and installer icons already used Frame branding.

Compatibility names remain: storage keys, CSS classes, event names, app identifier and native driver identifiers. Attribution and licenses remain intact. Theme presets were not redesigned.

## Playback

Two recovery paths could replace a paused session before its first frame: the completed-P2P-file watchdog and watch-party recovery. The regression harness reproduced unwanted recovery at 20 seconds and longer for P2P, and at the room recovery timeout. Recovery now checks the latest paused status, including queued recovery and live reconnect callbacks. There are no artificial refreshes, seeks or periodic player restarts.

Asynchronous window listener registration could finish after the player unmounted. Late registrations are now immediately removed. Tests cover unmount before import, during move subscription and during resize subscription.

Launching the installed app with a local MP4 stayed on Home. The startup bridge consumed its pending-file event before the app registered its handlers. Subscriptions now precede bridge startup; cleanup also handles a late import or bridge completion. Regression tests cover startup delivery and early unmount.

Existing first-frame/stall checks and the native mpv event-poll backoff reset are retained. No speculative GPU or rendering-option changes were made.

### Native observations

On the installed **0.4.0** Windows build, a generated three-minute H.264/AAC MP4 played through native mpv after a second file launch. It remained visibly paused at `00:40.792` for more than 120 seconds, then resumed from that frame and returned to Home. This baseline did **not** reproduce a general paused-frame blackout. It does not prove v0.4.5 fixes every cause of the reported problem.

The final v0.4.5 native pause matrix, MKV/streaming, seeking, fullscreen, minimize/restore and subtitle verification remain release gates. Simulated 10/20/30/60/120-second watchdog tests are distinct from hardware playback tests.

## Digital Releases

Radar now uses the configured TMDB key and region. It fetches every discovery page for the selected month with release type 4, then verifies each candidate against that country's `/movie/{id}/release_dates` records. Invalid calendar dates, theatrical/physical dates, other countries and out-of-window records are excluded. There is no silent region fallback. Results are deduplicated by TMDB ID and sorted by verified date and title.

Transport uses the existing six-request scheduler, deadline, retry handling and rate-limit backoff. Detail pages and complete calendars have bounded five-minute caches. Failed calendars are not cached or presented as complete. A discovery response exceeding TMDB's 500-page limit fails honestly.

Official references: [movie discovery](https://developer.themoviedb.org/reference/discover-movie) and [region support](https://developer.themoviedb.org/docs/region-support).

Live checks on 2026-11-16 covered September, October and November US release windows. A complete November run used 18 discovery pages plus individual release-date requests: **358 verified titles, 376 requests, about 25 seconds**, with no duplicates and correct ordering. These are TMDB records, not independent guarantees that a distributor will keep a future date. Coverage depends on TMDB contributions and the selected country. No scraping, supplementary paid service or fabricated records are used.

Automated cases cover valid/invalid dates, absent countries, duplicates, pagination, empty/past/future windows, missing keys, malformed responses, failed details, rate limiting and successful-cache isolation.

## Updates and backup

Updates & backup is grouped under System using the existing settings components. Release history and static feeds now explicitly target A67med/Frame. Malformed release-history responses fall back to Atom where possible; malformed release entries do not crash the list. Downgrade copy now asks users to export a backup and explains that older builds may not understand newer data.

The existing Tauri updater, signing public key and app identifier are unchanged. Backup export defaults omit credential-bearing sections; explicit selection still supports them with the existing encryption/consent flow. Restore retains validation, historical-format support, safety-copy and rollback handling.

The installed 0.4.0 UI opened System → Updates & backup, displayed its version, completed a manual no-update check and listed older installers. Backup tests use synthetic storage, not the developer's profile: export, encrypted round-trip, corruption, wrong passwords, future versions, refused writes, safety-copy failure, rollback and custom-code consent were covered by the passing frontend suite. Final v0.4.5 installer/update and UI export/import checks remain pending.

## Source organization

The preserved cleanup moves the ranking and recovery crates into `crates/frame-core/` and `crates/frame-install-recovery/`, updates callers/build paths, and extracts existing app lifecycle/navigation helpers. Unused alarm-clock/beta components and the obsolete manual release script were removed.

The macOS virtual microphone has a live platform-gated caller. Its earlier deletion was corrected: source is retained at `native/macos/virtual-mic/`, and the development-bundle lookup follows that location. Installed driver names, UID and bundle identifier remain unchanged. Windows builds do not establish whether this driver compiles on macOS.
