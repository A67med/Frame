# Frame v0.4.8 engineering notes

## Behavior and architecture

Digital Releases reads the existing Following people from `customCalendar.trackedPeople`. The current model supports people, not a separate followed-title collection. TMDB discovery uses pipe-separated person IDs in groups of 40, explicit regional type-4 release filters, and the selected month's boundaries. Discovery and existing person-credit retrieval run concurrently. The shared credit merger applies acting/directing/both roles and stable TMDB IDs; each movie retains all matching people. Only matching movie IDs receive a release-date lookup, in batches of six. Exact-country type-4 records are verified again, deduplicated and chronologically sorted.

The shared TMDB client supplies request scheduling, in-flight deduplication and public metadata caching. A bounded 128-entry, five-minute result cache includes credentials, language, people/roles, dates and region. Month changes abort further batches and ignore stale completions. Already-running shared metadata requests finish so other consumers can reuse them. Errors expose Retry rather than an incomplete calendar. There is no random-title or foreign-date fallback.

Per the final product instruction, Radar is fixed to Egypt (`EG`) and exposes no region selector. The description names Egypt and cards label EG. Shared regional settings remain available to other features and saved preferences are not overwritten; new profiles default to EG. The service still accepts an explicit region for validation and reuse.

## Visual changes

Digital Releases uses the existing Radar Row, cards and followed-person chips. The former boxed panel is removed. Month controls wrap with the shared row heading. Sidebar editing controls use a fixed 300px tray with viewport bounds and scrolling, retaining the sidebar's keyboard focus scope. Context menus clamp their width, wrapped menu items grow vertically, and Settings descriptions can wrap long content without escaping their group borders.

Default retains its existing layout and tokens. Project Hail Mary copies the supported colors, General Sans typography, Dracula layout, flat controls and bokeh preference from the supplied local theme. Personal navigation choices and embedded wallpaper are deliberately excluded. Dune uses angular sandstone/copper geometry and broad spacing; La La Land uses indigo/yellow, italic serif titles and curved posters; Doomsday uses green-black/gold, heavy headings and strong selection blocks; Zodiac uses silver/blue-green, fine rules and geometric Jura headings. The normalized, serializable composition field preserves these design variants through custom-theme save/export/import. Unknown or removed built-in selections fall back to Default; custom themes remain supported.

## Data and performance observations

Live TMDB checks used the local Following list without publishing account data or API credentials. For November 2026, the Egyptian personalized discovery fit on one page. One relevant title had an Egyptian type-4 date of November 13 while its US record was November 12, confirming that foreign dates must not substitute for Egyptian records. The same month's unfiltered US discovery reported 19 pages; filtering by followed people reduced it to one page and 16 candidates before role filtering. These are observations of this list and month, not a universal benchmark.

Direct discovery plus candidate record verification took approximately 689ms for Egypt and 408ms for the US during that sample; this excludes cold person-credit loading and must not be presented as end-to-end UI latency. Cache regression checks assert that repeated identical calls issue no new requests and that regions/Following changes remain isolated. Egyptian TMDB coverage is sparse; an empty month is a valid result.

## Validation and limitations

The full frontend suite passed 2,588 tests with one existing skip before the final region-selector adjustment. The final focused run passed 55 tests, including theme, digital-release, sidebar, region and locale coverage. TypeScript and changed-file lint passed with no diagnostics. The production frontend build passed in 2m 24s; its existing dependency-eval and large-chunk warnings remain. The Windows Rust check passed. Settings search passed all 39 queries.

The Rust check reported five existing warnings in untouched code (deprecated atomic operations and unused platform helpers). Settings validation reports the same nine failing categories against the unchanged base and this branch. The i18n audit reports existing shadowed keys and unspread locale files; it exits successfully in the repository's normal non-strict mode. These unrelated findings were not rewritten.

Production browser rendering covers all six themes on Home and Radar, plus realistic 1440x1000 and 960x720 layouts, expanded/collapsed navigation and Settings. The final built-app run verified Egypt labeling despite a saved US preference, absence of the region picker, readable sidebar trays and Escape in all six themes, hidden-tab restoration, rapid month switching, and no browser runtime errors. Library and Discover navigation were also exercised. Native desktop automation was unavailable in this environment; browser rendering is not a native playback test. Physical remote/gamepad, macOS, Linux and TV runtime testing remain outside this Windows release verification.

`backgrounds/` remains ignored and untracked. Original local reference files are untouched. The distributable Hail Mary theme has no embedded image or private path. No reference images are imported into the frontend or Tauri resources.

The official Windows workflow builds the NSIS installer with existing runtime dependencies, verifies bundle contents and publishes the updater manifest with its signature. Publication is considered complete only after the workflow succeeds and the public installer and manifest are verified.
