# Frame v0.3.0 — Cinematic Desktop

## Starting point and scope

Development starts at `origin/main` (`271b08ea`, v0.2.1) on
`feature/v0.3.0-interface-reinvention`, in an isolated worktree. The original
source-cleanup checkout was clean and remains untouched. No version, release,
native playback, provider, authentication, or persistence changes are planned.

The stable application's `REMOVED_PAGES` list already disables music, games,
anime, live TV, sports, manga, ebooks, calendar and social pages. Their source
files are not evidence of active product capabilities. Coverage follows the
actual `Shell` render branches; those exclusions remain unchanged.

## Baseline audit

- The Default preset comes from `Default.framestyle`: graphite, warm amber,
  General Sans, Dracula navigation. Its description incorrectly calls it violet.
- An expanded 256px navigation column competes with a floating search bar and
  individually positioned page headers. Utilities and destinations share a long
  vertical sequence, and the navigation disappears in Settings.
- Home's featured carousel and most discovery rows use the same horizontal
  rhythm. Continue Watching competes with discovery rather than reading as
  personal activity.
- Detail pages reserve at least 640px for a backdrop, placing actions at its
  bottom and synopsis below the fold. Artwork determines the reading order.
- Library can begin with another large hero. Its horizontal tabs overflow when
  several trackers are connected, and a long explanatory paragraph precedes work.
- Settings has useful searchable groups but a complicated three-row grid and
  nested expandable navigation. Its layout is disconnected from the app shell.
- Most capabilities already have reusable presentation components. Retain their
  handlers, focus attributes, context menus, virtualization and lazy loading.

Runtime observations and before/after captures are recorded separately in the
verification report; source observations above are not screenshot findings.

## Three directions considered

1. **Immersive theatre:** edge-to-edge artwork, hidden navigation, oversized
   title treatments. Strong emotional impact, but weak scanning and discoverability
   at 1280×800 and high Windows scaling.
2. **Film journal:** composed artwork, expressive titles, numbered editorial
   sections and varied proportions. Strong identity and content hierarchy, but
   requires a more restrained version for large libraries and settings.
3. **Media workstation:** fixed navigation, dense lists, persistent filters,
   quiet surfaces. Excellent daily utility, but insufficient cinematic character
   when applied indiscriminately to discovery.

**Decision:** Film journal for discovery and title dossiers, media workstation
for navigation and personal tools. Artwork is a deliberate region of a page,
not its only structure. The frame motif is expressed through ruled edges,
offset compositions and small amber location markers rather than decoration.

## Navigation and layout

- A narrow labelled navigation rail and an anchored command bar establish one
  desktop workspace. Existing navigation customization, parental gates, profile
  controls, hidden destinations and collapse preference remain available.
- The command bar combines history navigation, identity, search, session
  utilities and existing native window controls. Native dragging and resize
  regions keep their existing handlers.
- Discovery uses a lead feature with an adjacent editorial index and distinct
  personal activity treatment. Existing user row order, hidden rows and custom
  hero source remain authoritative.
- Details use a two-column title dossier: reading and actions alongside artwork,
  followed by clearly divided synopsis, episodes, credits and related material.
  Missing artwork must leave a complete readable page.
- Library uses a collection navigator beside the working content. Connected
  trackers remain conditional. Featured artwork remains optional and secondary.
- Settings keeps searchable categories and exact setting semantics, with a
  calmer workspace grid and a persistent page identity.
- Search becomes a substantial command workspace with a clear query header and
  separate discovery/result regions; its engine and keyboard behavior stay intact.

## Foundations

- Existing theme color tokens remain the source of truth. Add semantic layout
  tokens for rail, command bar, page gutter, content width and section rhythm.
- Use the installed display/body font infrastructure. Display type belongs in
  page titles; metadata and controls use readable sans-serif text.
- Compact controls, straight rules and restrained corners give dense tools a
  different cadence from artwork. Focus indicators must remain visible.
- Motion is short and purposeful; reduced motion disables new movement.
- New shared primitives describe page headings, navigation groups, section
  headings and workspaces, without introducing a component framework.
- Default and AMOLED receive the new composition. Imported themes retain their
  original layout identifiers, tokens, CSS hooks and saved settings; new layout
  defaults must not mutate imported `.framestyle` files or user storage.

## Verification standard

Review real frontend rendering, including network failure and missing-artwork
states, at multiple widths. Record capture conditions. Run formatting, lint,
typecheck, frontend regression tests, settings validators, theme tests and a
Windows build where available. Native playback/window behavior cannot be claimed
from a browser preview. The coverage and verification reports must distinguish
implemented, visually reviewed, inherited and unverified areas.
